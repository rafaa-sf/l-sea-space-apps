# NASA data pipeline (`scripts/nasa/`)

Scripts that acquire, verify and package the real NASA data used by L-SEA.
Everything they write lands in `public/data/` (browser-ready, committed) or in
a local cache outside the repository.

| Script | What it does | Output |
| --- | --- | --- |
| [`sites.mjs`](sites.mjs) | Curated south-pole POI catalogue (geometry, provenance, ephemeris config) | source of truth for the other scripts |
| [`fetch-horizons.mjs`](fetch-horizons.mjs) | JPL Horizons topocentric Sun/Earth az/el for every site, 30-minute steps, 2026-11-01 to 2026-12-31 | `public/data/ephemeris/<site-id>.json`, `index.json` |
| [`build-pois.mjs`](build-pois.mjs) | Samples each POI elevation from the LOLA web DEM grids and writes the site catalogue | `public/data/pois.json` |
| [`build-layers.mjs`](build-layers.mjs) | Verifies NASA Moon Trek WMTS layers (capabilities + a real tile + CORS) and writes the catalogue | `public/data/layers.json` |
| [`build-terrain.py`](build-terrain.py) | Converts PDS LOLA polar DEM JP2 products to browser grids (Python 3 + rasterio) | `public/data/terrain/*.{json,bin}`, `index.json` |
| [`download-lola.mjs`](download-lola.mjs) | Downloads the official PDS LOLA polar JP2 products (size + SHA-256 verified), caches them under `.cache/lola/`, and builds local terrain regions at the size you choose | `public/data/terrain/<id>.{bin,json}`, `index.json` |
| [`lola_crop.py`](lola_crop.py) | Rasterio helper called by `download-lola.mjs`: windowed crop + average resample of one JP2 into one terrain grid, same metadata conventions as `build-terrain.py` | `public/data/terrain/<id>.{bin,json}` |

## Requirements

- Node.js 24 for the `.mjs` scripts (no third-party dependencies).
- Python 3 with `rasterio` for the DEM scripts (`download-lola.mjs` and `build-terrain.py`).

## Local DEM downloader

The application lists every region in `public/data/terrain/index.json` in its DEM
area selector, so a downloaded region becomes selectable after the app reloads.

```bash
# Download both official LOLA products (size + SHA-256 verified) and build both
# standard regions: high detail 2048 px and wide area 1024 px.
npm run data:lola

# One standard region, or a different output size / resolution.
npm run data:lola -- --region=high-detail --size=1024
npm run data:lola -- --product=ldem_80s_80m --mpp=250

# Arbitrary local terrain: 400 km square at 1024 px (fits the wide-area product),
# or an explicit projected extent (metres) with an optional centre.
npm run data:lola -- --extent-km=400 --size=1024
npm run data:lola -- --extent=-150000,-150000,150000,150000 --size=512 --id=custom-300km-512px
npm run data:lola -- --extent-km=100 --center-x=-20000 --center-y=10000 --size=512

# Plan only, re-download, or replace an existing region whose bytes changed.
npm run data:lola -- --dry-run
npm run data:lola -- --region=both --force
npm run data:lola -- --extent-km=400 --overwrite
```

- Products are downloaded only from the PDS Geosciences Node and cached under
  `.cache/lola/` (gitignored). The exact byte size and SHA-256 are verified before
  use; `--force` re-downloads, a corrupt cache entry is re-downloaded
  automatically.
- Output is the same browser contract as the committed grids: `<id>.bin` (int16
  metres, little-endian, row 0 = maxY) and `<id>.json` (projection and grid
  metadata). `index.json` is updated in place, preserving existing regions and
  `defaultRegionId`.
- Standard regions regenerate byte-identically from the verified products, so
  `npm run data:lola` does not modify the committed grids (verified with SHA-256).
- Custom region ids look like `custom-400km-1024px`. The product is selected
  automatically from the extent (high-detail up to plus/minus 75,840 m, wide area
  up to plus/minus 304,000 m); out-of-coverage extents are rejected.
- `--overwrite` is required to replace an existing region whose generated bytes
  differ, which protects the committed grids from accidental changes.

## Typical run order

```bash
npm run data:lola                             # download + build the local DEM regions (first)
node scripts/nasa/fetch-horizons.mjs          # ephemerides (skips existing files)
node scripts/nasa/build-pois.mjs              # POIs + DEM-sampled elevations
node scripts/nasa/build-layers.mjs            # live verification of Moon Trek layers
python3 scripts/nasa/build-terrain.py --jpeg2000-dir /tmp/lola --out-dir public/data/terrain
```

`build-terrain.py` remains the reproducible builder for the two committed grids;
`download-lola.mjs` is the user-facing downloader that can also build custom
regions and sizes.

`fetch-horizons.mjs` is polite by design: one request at a time, 1.5 s default
delay (`--delay=<ms>`), retries on HTTP 429/5xx, and a `User-Agent` identifying
the project. It also supports `--force`, `--only=<id[,id]>` and `--dry-run`.

## Source verification

`node scripts/nasa/verify-sources.mjs` re-checks the official NASA sources and
the shipped provenance metadata: PDS LOLA products and labels (data set
`LRO-L-LOLA-4-GDR-V1.0`, scaling factor and offset), JPL Horizons, NASA Moon
Trek, LROC QuickMap, and that no non-NASA ephemeris library is used. Requires
network access; exits non-zero on any failure.
