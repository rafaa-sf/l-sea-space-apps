### Invariants (13)

All passed for 19,999 of 20,000 cases, except the single boundary case below:
`@inv/no-nan`, `@inv/bounds`, `@inv/roundtrip`, `@inv/horizon-consistency`,
`@inv/horizon-monotonicity` (93 warnings), `@inv/visibility-consistency`,

`@inv/ranking`, `@inv/cache-neutrality`.

### Findings

**L-1 (application defect — FIXED).** Status: fixed in `src/core/terrain.js`
(the sampling tolerance now matches `pointInsideBounds` and edge-clamps the
half-pixel band) with a regression suite in `src/core/terrain.test.js`; the
reproducer `node qa/logic/logic-mc.mjs --seed 20261114 --case 6000` now passes.
The text below records the finding as observed before the fix. Case
`seed 20261114`, `case 6000` reproduces a `NaN` in `sampleElevation`, slope and
aspect for a site at **lat −87.428°, lon 346.541°**. Root cause is in
`src/core/terrain.js`: `isInsideTerrain()` / `pointInsideBounds()` accept a
**half-pixel margin beyond the grid edge** (this site is 0.26 px outside
`maxY`), while `sampleElevationXY()` uses the pixel-centre convention and
rejects the same point (`row ≈ −0.76`) → `NaN`. Consequence: any site in that
outer half-pixel band is reported *inside* the terrain yet silently degrades
elevation, slope, horizon and autopilot scoring to `NaN`. Suggested fix: make
the two conventions agree — clamp sampling for points inside the accepted
margin (edge-clamped, as the terrain module claims) or reject sites beyond
`maxX/maxY − 0.5 px`. Not fixed by the test bench (it does not modify the
application).

```bash
node qa/logic/logic-mc.mjs --seed 20261114 --case 6000
```


**L-2 (accepted behaviour).** 93 `@inv/horizon-monotonicity` warnings: the
terrain-aware horizon computed with a denser azimuth sampling differs from the
coarser profile by more than the documented tolerance for single azimuths. This
is the expected discretisation effect; the check records it as a warning, not a
failure.

### Findings

**UI-1 (accessibility, applies at every resolution).** Interactive targets are
below the 24×24 CSS-px guideline: panel header toggles are 16–21 px tall and
several small buttons/links are 14–17 px tall. A design-system fix would clear
this everywhere at once.

**UI-2 (accessibility, applies at every resolution).** The smallest computed
font size is 9 px (9.5 px header labels/chips, 9 px compare-table cells and
timeline range). Raising the design tokens to ≥ 10–12 px would clear this.

**UI-3 (layout, narrow phones only).** Horizontal document overflow on the
narrowest viewports: `mob-344x882` (+2/+11 px), `mob-320x568` (+25/+35 px),
`mob-280x653` (+66/+91 px), in both EN and ES. No single overhanging element was
identified, so the cause is likely clipped/`overflow-hidden` content expanding
the document scroll width; reproducible with a real device if available.

## 5. Status

Findings are **reported, not fixed**: this test bench does not modify the
application. **L-1 is a real application defect** in the terrain boundary
convention and should be fixed in `src/core/terrain.js` (it silently produces
`NaN` for sites in the outer half-pixel band). UI-1/UI-2 are design-token fixes;
UI-3 deserves a real-device check. The harness itself is deterministic
(seed + case reproduction) and records the repository git SHA in every report.
