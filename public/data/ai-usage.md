# AI usage and tools declaration

Declaration of the artificial-intelligence tools used to build **L-SEA Space
Apps**, the team's project for the **NASA International Space Apps Challenge ·
Málaga 2026**, and how they were used. This is the document referenced from the
application's "AI use" link (served as `/data/ai-usage.md`).

> **Summary:** the solution was built by a small human team working with an
> **AI agent team** (DeepSeek Harness sessions). AI generated the code,
> documentation, research and data-acquisition scripts under human direction;
> humans defined the project, set the feature list and architecture, reviewed and
> accepted the results, and remain **fully responsible** for the submitted
> content. NASA data is real and was retrieved from NASA services by scripts; it
> was not generated by AI.

## 1. Tools used

| Tool | How it was used |
| --- | --- |
| **DeepSeek Harness** (agentic coding platform, <https://github.com/deepseek-ai>) | Hosted the AI agent team sessions that produced the repository: research, code, tests, data acquisition scripts and documentation |
| **DeepSeek models** (`deepseek` / `deepseek-flash` coding agents) | The language models behind the agent sessions |
| **Node.js 24, Vite, Vue 3, Three.js, Vitest** | Application stack the AI wrote code for (human-chosen) |
| **Python 3 + rasterio** | One-off terrain conversion script written with AI assistance |
| **JPL Horizons, NASA Moon Trek, PDS Geosciences (LOLA), LROC QuickMap** | Real NASA data sources queried and verified by the scripts (no generative content) |

No other generative AI service (image, video, voice) was used. No AI-generated
images, videos, voices or synthetic people appear in the repository or in the
demo material.

## 2. The AI agent team and its roles

The work was split across durable AI agent sessions that shared one working
directory and a task board:

| Session | Role | Responsibility in this project |
| --- | --- | --- |
| **Lead** | Orchestrator / integrator | Broke the challenge into tasks, assigned scopes, reviewed and integrated results, built the terrain grids, coordinated the final submission |
| **commander** | Data research and documentation | Verified the NASA APIs with real requests; produced `public/data/pois.json`, `public/data/ephemeris/`, `public/data/layers.json`; wrote `docs/api-integrations.md`, `docs/data-sources.md` and this declaration; final data report |
| **coder** | Domain logic | `src/core/` (terrain, geometry, Sun/Earth visibility engine, ephemeris interpolation, power, communications, autopilot) and the data-service adapters, plus unit tests |
| **ui** | Frontend | Vue 3 application shell, panels, i18n (English/Spanish), Three.js scene and the no-WebGL 2D fallback renderer |
| **reviewer-pusher** | CI, review and version control | GitHub Actions, branch/commit hygiene, review of the final diff, deployment documentation and the only session allowed to run `git add/commit/push` |

The human team directed the sessions: it chose the challenge and the product
vision, approved the architecture and data strategy, defined the feature list and
priorities, ran the verification commands, decided what to accept or reject, and
performed the actual submission.

## 4. What humans did

- Selected the NASA Space Apps challenge and defined the product vision and scope.
- Chose the technology stack and approved the architecture, data model and
  interface contracts (`docs/architecture.md`).
- Defined the feature list and priorities, and made the final product decisions.
- Directed the AI sessions, reviewed their output and rejected or corrected
  parts of it when necessary.
- Executed the verification commands (real API requests, data statistics,
  `npm run build`) and checked the facts against the cited sources.
- Wrote and submitted the official Project page, demo and final materials, and
  accepted responsibility for them.

## 5. Where the data comes from (and where AI stops)

- **Sun/Earth positions:** computed by **NASA/JPL Horizons** (DE441) — not by AI.
- **Terrain elevations:** **NASA LRO LOLA** gridded DEMs from the PDS
  Geosciences Node — not by AI.
- **Map layers:** live **NASA Moon Trek** WMTS services — not by AI.
- **Site coordinates:** curated from peer-reviewed publications and the official
  NASA Artemis III site mosaics, cited per site in `docs/data-sources.md`.
- The AI wrote the scripts that retrieve, verify and reformat this data; the
  scientific values remain NASA's.

## 6. Verification and limitations

- The data pipeline was verified with real requests: 20 JPL Horizons queries
  produced 2 928 samples per site with zero gaps, and all 21 Moon Trek layers
  were verified with live tile requests and CORS checks before being written to
  `public/data/layers.json` (see `docs/api-integrations.md`).
- The application builds successfully (`npm run build`) and includes unit tests
  for the core algorithms (Vitest).
- AI-generated code and text can contain mistakes. Every external claim in the
  documentation carries the exact endpoint or citation so it can be re-checked;
  the team reviewed the final result before submission.
- Known limitations of the data (resolution, coverage, sampling) are stated in
  `docs/data-sources.md` instead of being hidden.

## 7. Labelling of generated content

- This repository's code and documentation are AI-assisted; this declaration is
  the visible label for that content, and the application links to it from the
  interface.
- All materials are written in English and use only text-based attribution; no
  NASA logo, flag, mission identifier or other restricted brand element is used.
- No identifiable person, and in particular no minor, appears in any AI-generated
  content.
