# AI usage and tools declaration

Declaration of the artificial-intelligence tools used to build **L-SEA Space
Apps**, the team's project for the **NASA International Space Apps Challenge ·
Málaga 2026**, and how they were used. This is the document referenced from the
application's "AI use" link (served as `/data/ai-usage.md`).

> **Full disclosure:** **all content in this repository was produced by AI
> agents** — application code, data-acquisition scripts, datasets formatting,
> tests, CI, documentation, the submission package and the QA test bench
> (Monte Carlo logic bench and device/resolution UI matrix, shipped under
> `qa/`). Two AI agent teams worked on two machines under human direction.
> The human team defined the challenge, product and priorities, authorised actions,
> reviewed and accepted the output, and remains **fully responsible** for the
> submitted material. Real NASA data was retrieved from NASA services by scripts
> and was **not** generated by AI.

## 1. Tools used

| Tool | How it was used |
| --- | --- |
| **DeepSeek Harness** (agentic coding platform) | Hosted the two AI agent teams that produced the repository and the submission material |
| **DeepSeek models** (`deepseek` / `deepseek-flash` coding agents) | Language models behind every agent session |
| **Node.js 24, Vite, Vue 3, Three.js, Vitest** | Application stack written by the agents |

| **git / GitHub CLI / GitHub Actions** | Version control, tags-based machine coordination and CI, operated by the agents |
| **pdftotext / pdftoppm and image reading** | Extraction of the official event material (participant and judges guides, challenge posters) |
| **JPL Horizons, NASA Moon Trek, PDS Geosciences (LOLA), LROC QuickMap** | Real NASA data sources queried and verified by the scripts (no generative content) |

No other generative AI service (image, video, voice, music) was used. No
AI-generated images, videos, voices or synthetic people appear in the repository
or in the demo material.

## 5. Where the data comes from (and where AI stops)

- **Sun/Earth positions:** computed by **NASA/JPL Horizons** (DE441) — not by AI.
- **Terrain elevations:** **NASA LRO LOLA** gridded DEMs from the PDS
  Geosciences Node — not by AI.
- **Map layers:** live **NASA Moon Trek** WMTS services — not by AI.
- **Site coordinates:** curated from peer-reviewed publications and the official
  NASA Artemis III site mosaics, cited per site in `docs/data.md`.
- The AI wrote the scripts that retrieve, verify and reformat this data; the
  scientific values remain NASA's.

## 6. Verification and limitations

- The data pipeline was verified with real requests: 20 JPL Horizons queries
  produced 2 928 samples per site with zero gaps, and all 21 Moon Trek layers were
  verified with live tile requests and CORS checks before being written to
  `public/data/layers.json` (see `docs/data.md`).
- The application builds successfully (`npm run build`) and its unit/contract
  suites pass (Vitest: **275 tests** in 19 files at the time of writing, plus
  8 MCP checks in CI).
- Responsive layout and no-WebGL fallback checks are documented in
  [`docs/qa.md`](qa.md); the QA test bench ships under `qa/` and records the
  repository git SHA. The full matrix covers all 51 viewports × EN/ES plus
  no-WebGL probes; the last full run on the merged state passed 103/104 checks,
  and the single 280 px Spanish overflow it found was fixed and re-verified on
  the affected boxes. The whole-page audit of every tab and drawer passed 43/43.
- The playback state machine was verified with a **20 000-sequence** Monte Carlo
  simulator over the real store under fake timers (zero failures after the fix),
  and the scientific core with a **10 000-case** randomised run (zero invariant
  failures; 48 horizon-monotonicity warnings inside the documented tolerance).
- Design-token contrast was re-checked after the UX changes: all text pairs
  ≥ 4.5:1 and control borders ≥ 3:1 (primary button label 5.80:1).
- Exact test counts are maintained in the test-bench reports rather than duplicated
  here; they are generated by the same AI agents and can be reproduced from the
  scripts.
- AI-generated code and text can contain mistakes. Every external claim in the
  documentation carries the exact endpoint or citation so it can be re-checked; the
  team reviewed the final result before submission.
- Known limitations of the data (resolution, coverage, sampling) are stated in
  `docs/data.md` instead of being hidden.
