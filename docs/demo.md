# Project Demo

The Project Demo is a single public link: a presentation of at most **7 slides
including the cover**, or a **video of at most 30 seconds**. Everything is in
English. No identifiable minors and no NASA logos as project branding.

Assets: the slide deck is `demo/L-SEA-Project-Demo.pptx` (with its PDF export
alongside it), generated by `scripts/demo/build-demo-deck.py`; see
[`demo/README.md`](../demo/README.md). Application screenshots:
`docs/screenshots/app-3d.png` and `docs/screenshots/app-2d-es.png`.

Narration length: 77 words, about 28 seconds at a measured 165 words per minute; trim
the last clause if the export runs long. On-screen text is in English and matches the
narration.

Honesty rule for the video: record the real application. If a scenario is captured
from the built source or automated evidence instead, say clearly that it is built and
that end-to-end or accuracy validation is still pending. Do not fake a working
scenario: judges compare the video with the Project page and the repository.

## 4. Demo runbook and Q&A

### Demo paths

- **Path A, current build:** pre-load two sites and two dates before the pitch (avoid
  live loading over venue Wi-Fi); click site, date, compare, open brief. Keep a second
  browser tab with the same state as backup and a screen recording of the flow as
  fallback.
- **Path B, live deployment:** run the same flow on the public Vercel URL; if the
  venue network fails, switch to the local `dist/` preview or the screen recording.
- **Both:** pre-open the repository, README and `docs/architecture.md` in tabs for Q&A
  evidence; test public links logged out.

### Likely questions and short answers

| Likely question | Answer (evidence-based) |
| --- | --- |
| Where does the NASA resource intervene? | LOLA terrain is the horizon input to every Sun/Earth visibility decision; it is shipped and validated (grids, ranges, cross-region r = 0.9993). Horizons provides Sun and Earth positions; Moon Trek provides layers and deep links. All three are implemented and consumed by the application. |
| What works today, what is pending? | Built, merged on `main` and deployed: 13-panel UI, EN/ES, real LOLA terrain, Horizons ephemerides and Moon Trek layers consumed by the application, horizon and ray-tracing engine, power and communications, comparison, autopilot scoring, JSON export, 3D and 2D views, CI green (128 app tests plus 8 MCP tests). Pending: the public Project Demo link, accuracy validation against live Horizons, usability testing. |
| What evidence supports the conclusions? | Terrain validation PASS (2 source regions + 4 area presets, 0 failures); cross-region agreement r = 0.9993 with mean absolute difference 28.8 m; production build green; live end-to-end check recorded in [qa.md](qa.md). Accuracy against Horizons is the next validation and is not yet claimed. |
| What is the main limitation? | Prototype status, terrain resolution (74 m/px default) and static hosting, which requires pre-computed ephemerides. It is disclosed rather than hidden. |
| Which decision adds the most value? | Comparing scenarios rather than inspecting one site, and exporting a reproducible brief. That is the gap the challenge brief names in existing tools. |
| Why not just use Moon Trek, QuickMap and Horizons? | They are authoritative but built for detailed analysis; the brief says they are hard for non-specialists to use for rapid comparison. We consume their data and link back to them. |
| How is this creative? | A mission-profile autopilot that ranks sites against power, relay and sunlight-days needs, plus a bilingual, no-WebGL, static experience for both planning and education. |
| Is it scientifically valid? | The physics is standard (spherical Moon, no atmosphere, terrain plus lunar curvature for the horizon); tolerances and coverage are documented; validation against Horizons is the next step. |
| What would you do with more time? | Validate against live Horizons, run a timed usability test, ship lazy-loaded terrain tiles. |
| Are you using AI? | Yes, and it is declared in full in [ai-usage.md](ai-usage.md), also served by the application at `/data/ai-usage.md`. |
